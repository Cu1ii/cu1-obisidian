## 1. 背景与目标

### 1.1 场景

教育(edu)场景:教学训练、班级作业、校内 / 班级比赛。

### 1.2 一期目标

- 提供完整题库与判题能力,覆盖 ACM 经典题与函数题(LeetCode 式)。
- 提供比赛能力,支持 ACM 与 OI 两种赛制。
- 基于 ABAC 模型,实现题目粒度的细粒度权限管控。
- 支持班级维度的成员与权限管理。

### 1.3 非目标(一期不做)

详见 [6 一期不做清单](#6-一期不做清单)。

## 2. 角色与用户

| 角色 | 说明 | 关键能力 |
| --- | --- | --- |
| 顶级管理员 | 系统超级管理员;可有多个;首次启动有默认账号 | 全权数据资源越权 + 系统级配置 + 角色管控;**不可改他人账号身份信息**(详见 §3.4.7) |
| 教研员 | 出题与教学的核心运营角色 | `create_problem`(创建/编辑题目)+ `link_class`(关联班级,如老师绑本班)+ 可创建比赛 |
| 普通用户 | 注册用户(含"团队号":多人共用的普通账号) | 做题、参赛;依自身被授予的数据权限 |
| 匿名访客 | 未登录用户 | 仅可查看公开题面;提交、报名等动作必须登录 |

> 一期不做"团队赛"模式(多人共享提交)。需要团队场景时,以"团队号"(等价普通用户)替代。
>
> 一期不再设独立"组织管理员"角色。班级关联由教研员通过 `link_class` 完成;班级本身的增删与跨班级成员维护由顶级管理员承担。

## 3. 功能模块

### 3.1 题库

#### 3.1.1 题目元信息

核心元数据(题目域固有):

- 标题
- 创建者(初始 owner)
- owner 列表(允许多 owner / 协作出题)

衍生数据(由提交、统计或外部分类派生,不属题目核心):

- 通过率(由提交记录聚合,代替难度档位,直接显示百分比)
- 标签(分类索引,多个,自定义)

> 题目"可见性"不作为元数据字段存在,而是基于 ABAC 对当前主体计算 `view_submit` 决策的结果。详见 §3.4。

#### 3.1.2 题面

- 富文本格式:Markdown + LaTeX 公式 + 图片。
- 多语言题面:出题人手动创建其他语言版本;创建时可勾选"机翻填充"作为初稿。
- 不强制要求所有语言齐全,以创建版本为准。

#### 3.1.3 题目类型

- ACM 经典:stdin / stdout 全文比对(支持 SPJ)。
- 函数题(LeetCode 式):每语言提供 stub 模板 + harness 包装,选手实现指定函数。

#### 3.1.4 测试数据

- 数据来源
  - 压缩包上传
  - 单文件上传
  - 平台跑造数脚本生成(沙箱执行,不可信代码)
- 数据结构
  - 单组多输入输出(单测试点多 case)
  - 多组单输入输出(多测试点)
- 数据版本管理:每次更新生成新版本,可回滚。
- 历史版本保留:默认保留最近 30 天,超期自动清理(当前版本始终保留);保留时长为系统配置项,可调整。
- 数据下载:有查看数据权限者可下载。

#### 3.1.5 SPJ(Special Judge)

- 一期仅支持 C++。
- 强制基于 testlib.h 协议:
  - 调用约定:`./checker <input> <output> <answer>`
  - 退出语义:`_ok` / `_wa` / `_pe` / `_fail` / `_dirt` / `_points`
- 造数脚本(Generator)、数据校验脚本(Validator)、Checker 全部走 testlib.h 协议。

#### 3.1.6 输出比对模式

题目维度配置,枚举:

- 严格(完全一致)
- 忽略行尾空白
- 浮点精度(可配阈值)
- SPJ(覆盖以上,使用题目挂载的 checker)

#### 3.1.7 资源限制(题目维度)

- 运行时间(单测试点)
- 内存上限

> 一期仅控时间 + 内存,其他维度(栈、进程数、输出大小)不在一期范围。

#### 3.1.8 列表与检索

- 检索:题目 ID 精确匹配 + 标题模糊匹配。
- 过滤:标签 / 通过率 / 已通过 / 未通过 / 我创建。
- 不做:难度档位过滤(无难度档位概念)。

### 3.2 判题

#### 3.2.1 支持语言

| 语言 | 多版本并存 |
| --- | --- |
| C | C89 / C99 / C11 等(具体版本清单后定) |
| C++ | C++11 / C++14 / C++17 / C++20 等 |
| Java | JDK 版本可并存 |
| Go | 单版本起步,允许后续扩展 |
| Python3 | — |
| Python2 | — |
| Kotlin | — |

> 多版本并存指出题人/选手可指定具体版本编译运行。

#### 3.2.2 判题状态全集

`Pending` / `Judging` / `AC` / `WA` / `TLE` / `MLE` / `RE` / `CE` / `PE` / `OLE` / `SystemError`(以及必要时的 `Skipped`)。

#### 3.2.3 提交频率限制

- 系统级配置项(全局阈值,后续具体数值待定)。
- 触发后返回明确提示。

#### 3.2.4 代码长度

不卡上限。

#### 3.2.5 Rejudge

- 粒度:**比赛内 + 题目维度**(对该比赛内某一题的全部提交批量重判,可按题分别触发,可同一比赛多次触发)。
- 一期不做:单提交、跨比赛、全题(题库维度)、全库 rejudge。
- 触发权限:见 §3.4 `rejudge_in_contest` 动作。

### 3.3 比赛

#### 3.3.1 创建配置

| 配置项       | 说明                                            |
| --------- | --------------------------------------------- |
| 比赛标题、描述   | —                                             |
| 起止时间      | 创建时自由指定                                       |
| 赛制        | ACM / OI                                      |
| ACM 罚时    | 默认 20 min / 错误提交,可配                           |
| OI 取分     | 每题取最后一次提交得分                                   |
| 封榜        | 指定"起始时间 → 比赛结束"区间封榜                           |
| 进入控制      | 公开 / 密码 / 邀请名单 / 参赛名单                         |
| 比赛详情可见性 | 赛前:仅创建者;赛中:仅参赛者;赛后:按下方"赛后开放"配置;比赛**列表页**始终可见(不受此项控制)|
| 赛后开放 | `post_contest_open: bool`,默认 false。true → 赛后任何人可见比赛详情(题面 / 榜单)与参赛者提交记录元信息 |
| 赛后他人代码可见 | `post_contest_code_visible: bool`,默认 false。true → 所有参赛者可互看代码;false → 仅本人可见自己代码;owner / 顶管 始终可见。仅在 `post_contest_open = true` 时此项才有意义 |
| 赛后题目自动开放 | `post_contest_problem_open: bool`,默认 false。true → 赛后将题目自动开放给参赛者(获得永久 `view_submit`)。仅对 owner 全为创建者本人的私有题目生效;若创建者仅持有 shared 角色,则不开放 |

#### 3.3.2 报名机制

- 公开比赛:用户自行报名(可能要求密码)。
- 教研员:批量 / 单个手动添加学生进入比赛(典型场景:老师拉本班学生)。
- 不做:报名审核、虚拟参赛(virtual)。

#### 3.3.3 比赛题单

- 从题库选题(无"克隆题"概念)。
- 加题前置:题目须满足以下任一 — 公开 / 创建者是 owner / 创建者持有 shared 角色。
- 比赛中提交不影响题库题目本身的提交记录与通过率统计口径(待澄清,见 §7)。

#### 3.3.4 榜单

- 样式参考:[xcpcio board](https://board.xcpcio.com/ccpc/12th/guizhou-invitational)
- 字段
  - 排名
  - 通过题数(ACM)
  - 罚时(ACM)
  - 总分(OI)
  - 各题状态色块(AC / WA / Pending …)
  - 一血标记
  - 气球
- 刷新:实时。
- 封榜:封榜区间内对参赛者隐藏新增提交结果,仅显示尝试中状态;赛后解封。

#### 3.3.5 Clarification

- 比赛维度公开广播(所有参赛者可见提问与回答)。
- 一期不做私聊式 clarification。

#### 3.3.6 不支持项(比赛维度)

- 补题
- 虚拟参赛
- 团队赛(共享账号)

#### 3.3.7 提交权限

- 仅参赛者可提交比赛题(`submit_in_contest`)。
- 比赛中临时权限:参赛者对比赛题获得**临时** `view_submit`,赛中有效。
- 赛后题目处理:
  - 题目本身公开 → 维持公开,不变。
  - 题目 owner 全为创建者 + `post_contest_problem_open = true` → 永久开放给参赛者(`view_submit`)。
  - 创建者仅持有 shared 角色的题 → 不开放(无权代他人放题)。
  - 其他情形 → 临时权限到赛末失效。
- 不开放范围 = 题目详情 + 该题提交记录 + 代码 全部不可见。

### 3.4 权限(ABAC)

#### 3.4.1 模型

```
主体 (subject)     : user_id, role, classes,
                     is_owner_of(problem),
                     is_shared_to(problem),
                     is_participant_of(contest),
                     is_creator_of(contest)
资源 (resource)    : Problem | Contest | Submission | Class
环境 (environment) : time, contest_active
动作 (action)      : 见 §3.4.2 各资源动作表
```

> - **主体属性**:`role` ∈ { 顶级管理员, 教研员, 普通用户 };`classes` 为该用户所属班级集合(扁平,无层级);`is_owner_of` / `is_shared_to` / `is_participant_of` / `is_creator_of` 均为派生属性,运行时实时计算。
> - **没有"班级权限点"**。班级只是授权范围目标(开放给某班级 → 该班级所有成员命中)。
> - **环境属性**:`time` 为当前时刻;`contest_active` 由 `now ∈ [contest.start, contest.end]` 派生。
> - **题目无 `visibility` 字段**;"可见性"是对当前主体计算 `view_submit` 动作的决策结果。
> - **封榜不属权限模型**,仅榜单渲染策略(见 §3.3.4)。
> - **匿名访客**:对公开题视作持有 `view_submit`,看题面无需登录;真正点提交时由登录态校验兜底(非权限模型范畴)。

#### 3.4.2 动作集合(按资源分类)

**Problem**

| 动作 | 含义 | 默认命中 |
| --- | --- | --- |
| `view_submit` | 查看题面 + 从题库提交(合并为同一权限点) | 公开 / owner / 显式授权(用户 / 班级 / shared) |
| `edit` | 编辑题面 / 数据 / 限制 | owner / 顶管 |
| `view_data` | 查看 / 下载测试数据 | owner / 顶管 / shared 角色 |

> 匿名访客视作天然持有"公开题 `view_submit`"权限;真正发起提交动作时由登录拦截兜底(看可不登录,提交必登录)。

**Contest**

| 动作 | 含义 | 默认命中 |
| --- | --- | --- |
| `view_contest_detail` | 查看比赛详情(含题单) | 赛前:仅创建者;赛中:仅参赛者;赛后:`post_contest_open` 决定;比赛**列表页**始终公开,不在此动作范围 |
| `view_scoreboard` | 查看比赛榜单 | 跟随 `view_contest_detail` |
| `enter_contest` | 报名 / 进入 | 按报名规则(公开 / 密码 / 邀请名单 / 参赛名单) |
| `submit_in_contest` | 比赛中提交比赛题 | 仅参赛者,且 `contest_active = true` |
| `manage_contest` | 改配置 / 加人 / 改题单 | 创建者 / 顶管;赛中不允许改配置 |
| `rejudge_in_contest` | 触发本比赛批量 rejudge(可按题) | 创建者 / 顶管 |

**Submission**

| 动作 | 含义 | 默认命中 |
| --- | --- | --- |
| `view_submission_record` | 查看提交记录元信息(状态 / 用时 / 内存 / 得分) | 比赛中:参赛者可看本比赛全员;比赛外:本人 + 题目 owner / 顶管,叠加按题目 `view_submit` 过滤 |
| `view_submission_code` | 查看代码 | 比赛中:仅本人;赛后:按比赛 `post_contest_code_visible` 决定他人是否开放;本人 / 题目 owner / 顶管 始终可见 |

> 提交记录列表始终按题目 `view_submit` 过滤(没有题目权限 → 看不到对应提交)。

**Class**

| 动作 | 含义 | 默认命中 |
| --- | --- | --- |
| `link_class` | 教研员把自己关联到某班级(如老师绑本班) | 教研员 / 顶管 |
| `manage_class` | 创建 / 删除班级、跨班级成员维护 | 顶管 |
| `manage_class_members` | 增删某班级成员、批量导入 | 该班级关联的教研员 / 顶管 |

#### 3.4.3 主体粒度(可叠加)

- 用户级:显式列举 `user_id`
- 角色级:`顶级管理员` / `教研员` / `普通用户`
- 班级级:授权给整个班级(命中该班级所有成员)
- 派生属性级:`owner` / `participant` / `creator` / `shared`

#### 3.4.4 授权策略模板

题目无 `visibility` 字段。教研员创建 / 编辑题目时,可挑选预设模板,本质是若干 ABAC 规则的快捷打包。可叠加多条规则。

预设模板:

- **公开**:对所有主体(含匿名)放开 `view_submit`;匿名提交时由登录态拦截兜底。
- **私有**:仅 owner 与显式授权主体放开。
- **shared 授权**:把 `view_submit + view_data` 打包授给指定用户 / 班级(可叠加多条)。
- **仅特定班级**:对指定班级成员放开 `view_submit`(不含 `view_data`,如需 `view_data` 走 shared)。

教研员可在模板基础上叠加显式 user / role / class 授权。

#### 3.4.5 策略冲突解决

**多条策略命中时,取权限最高(allow 优先)。**

#### 3.4.6 普通用户能力

- 普通用户**不能**创建题目(出题入口仅向教研员 / 顶管开放)。
- 仅能 `view_submit` 自身有权限的题目。
- 自身提交始终可看(本人对自己 submission 默认全权)。

#### 3.4.7 顶级管理员

可越权所有数据资源动作(题目 / 比赛 / 提交 / 班级);承担系统级配置变更与角色管控。

**红线:不可改他人账号身份信息**。包括但不限于他人的:
- 密码 / 改密
- 邮箱
- 昵称 / 头像 / 个人资料
- 绑定信息

允许的账号管理动作仅限:
- 创建账号
- 禁用 / 启用 / 删除账号
- 改角色(顶管 / 教研员 / 普通用户 切换)
- 改班级归属(加入 / 移出)

> 用户身份信息仅本人可改。密码忘记 → 一期不做密码找回(见 §6),由顶管走"删账号 + 重建"或后续版本补足找回流程。

#### 3.4.8 多 Owner

允许一题多 owner,owner 间权限对等(均拥有 `edit` / `view_data` / 题目所有提交的 `view_submission_*`)。

#### 3.4.9 比赛上下文与原始权限的关系

- 比赛中 `submit_in_contest`:仅参赛者,与题目原始 `view_submit` 解耦(题库上下文走 `view_submit`,比赛上下文走 `submit_in_contest`)。
- 比赛中临时权限:参赛者对比赛题获得**临时** `view_submit`,**仅在比赛上下文有效**,不影响题库上下文。
- 赛后是否把临时权限转为永久 → 见 §3.3.7 与 §3.3.1 `post_contest_problem_open` 配置。

### 3.5 用户系统

#### 3.5.1 注册与登录

- 邮箱注册,无邮箱验证(一期)。
- 批量导入:Excel / CSV(教研员、顶级管理员可用)。
- **批量生成学生账号**(教研员在班级初始化场景使用):
  - 入口:班级详情 → 成员管理。
  - 规则字段:用户名前缀、序号起止区间、序号位数(零填充)、初始密码策略(统一密码 / 随机密码)、邮箱后缀(可选,允许留空,以平台占位邮箱兜底)、昵称模板(可选,例 `班级名_序号`)。
  - 生成预览:提交规则前先列出将创建的账号清单,确认后入库。
  - 副产物:生成完毕导出账号 + 初始密码清单(xlsx),仅当次可下载。
  - 自动入班:生成账号默认加入当前班级。
  - 冲突处理:用户名 / 邮箱已存在 → 跳过并在结果中标记。
- 一期不做:SSO / LDAP / 密码找回。

#### 3.5.2 个人主页

- 提交记录列表
- 累计 AC 题数
- 已通过题列表

#### 3.5.3 站内消息(铃铛)

一期支持以下 5 类站内通知,均为站内信形式,不发邮件:

1. 比赛即将开始提醒(开赛前 N 分钟,N 待定)
2. 比赛已结束
3. clarification 有新回复 / 新公告
4. 自己提交被 rejudge 完成
5. 题目权限被授予

### 3.6 班级

- 扁平结构,无层级(无学校 / 院系等上位概念,即"班级"本身就是组织粒度)。
- 顶级管理员能力:
  - 创建 / 删除班级
  - 跨班级成员维护
- 教研员能力(对自己关联的班级):
  - 增删该班级成员
  - 批量导入(Excel / CSV)
  - **按规则批量生成学生账号并入班**(详见 §3.5.1)
  - 在该班级维度授予题目 / 比赛权限
- 教研员通过 `link_class` 关联自己负责的班级(如老师绑本班)。
- 用户可同时归属多个班级。

### 3.7 页面清单

按业务模块分组,逐页列承载的功能点。

#### 3.7.1 公共

**首页**
- 入口导航
- 近期比赛、最新题目展示
- 个人未完成题列表(登录后)

**登录**

## 8. 附录

### 8.1 术语表

- **OJ**:Online Judge,在线判题系统。
- **ACM 赛制**:按通过题数 + 罚时排名,错误提交累计罚时。
- **OI 赛制**:按总分排名,本一期取每题最后一次提交得分。
- **SPJ**:Special Judge,题目自带的输出校验程序。
- **testlib.h**:Codeforces 官方 C++ 头文件,提供 SPJ / Generator / Validator / Checker 的标准协议与读取器。
- **ABAC**:Attribute-Based Access Control,基于属性的访问控制。
- **rejudge**:对已有提交按当前数据 / 限制重新判定。
- **封榜**:在指定时间区间内对参赛者隐藏新结果。
- **一血**:某题首个 AC 的提交。
