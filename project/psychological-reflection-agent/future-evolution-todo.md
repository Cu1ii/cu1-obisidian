# 心理反思 Agent 系统未来演进 TODO

本文只记录已识别的演进方向，不代表已纳入 MVP，也不预先锁定实现归属或技术方案。

## Agent 基座

### 可选组织上下文与 SSO

- 在保持 User 独立性的前提下，支持部分 User 进入组织或租户上下文。
- 支持租户内 SSO User 与非 SSO User 并存。
- 不假设一个现实中的人只能对应一个 User；不同 User 默认不自动合并、不自动共享数据。
- 在引入组织能力时，明确各模块数据使用 User 作用域、组织作用域或两者组合的规则。
- 心理分析数据即使在组织登录场景下，仍默认仅对对应 User 可见，不能自动对组织成员或管理员开放。

## 心理分析 Agent 模块

### 长期资料的业务使用

- 在用户明确授权和选择的前提下，允许心理剖析引用长期外部资料。
- 定义外部资料在普通聊天、心理剖析和长期复盘中的可用范围。
- 资料内容不自动形成长期记忆；基于资料形成的心理观察仍须经过正常确认流程。
- 在复盘中展示资料来源、使用范围和可用状态，避免将资料内容直接等同于心理结论。

## 外部数据源能力（归属待定）

### 数据源接入

- 支持 Obsidian、GitHub Repository 等长期外部数据源。
- 业务模块通过接口注册和管理数据源定义；数据源定义与实际数据内容分离。
- 系统启动时加载已注册的数据源定义和连接能力，而不是将数据源中的全部内容直接加载入上下文。
- 支持运行时新增、更新、停用和删除数据源，无须重启服务。

### 数据访问与生命周期

- 支持数据源授权、凭证管理、按需读取、搜索、同步、版本追踪和失效处理。
- 支持来源追踪，使业务模块能够说明某次分析或复盘使用了哪些资料。
- 支持删除资料或撤销授权后停止后续访问和使用。
- 明确数据源能力最终由哪个系统模块承载；当前不归入 Agent 基座 MVP。

## 记录原则

- 每项 TODO 在进入实现前，重新确认其业务归属、隐私边界、授权方式和 MVP 必要性。
- 不因为已记录为未来方向，就提前在当前模块中引入对应的接口、数据模型或运行机制。
