# Agent 基座能力

## 1. 定位与范围

Agent 基座为业务模块提供通用的 Agent 运行能力。MVP 面向 C 端，只以 User 为数据归属和隔离边界；不实现租户、组织成员关系或 SSO。

基座不承载领域业务流程、领域输出合规、领域风险判断、业务质量判断或统一业务监控。业务模块通过基座调用通用能力，并在获得模型结果后自行决定是否向用户展示、继续处理或写入业务数据。

心理自我反思模块的领域规则见 [[psychological-analysis-agent-module]]。

## 2. User 级隔离

### 2.1 数据归属

- 会话、上下文、记忆、调用记录和成本数据均归属于当前 User。
- 不同 User 的数据默认完全隔离，业务模块不得跨 User 读取。
- MVP 不假设一个现实中的人只能拥有一个 User，也不引入用户与租户的成员关系。

### 2.2 访问约束

- 每次基座能力调用都必须携带当前 User 上下文。
- 基座基于当前 User 执行读取、写入、修改和删除，不由业务模块自行拼接或绕过隔离条件。
- 用户级隔离是 MVP 的唯一数据边界；租户或组织隔离属于未来演进事项，见 [[future-evolution-todo]]。

## 3. 会话与上下文管理

### 3.1 会话生命周期

- 创建、继续、查询和删除会话。
- 持久化用户与 Agent 的原始对话记录。
- 支持业务模块读取当前会话及其明确指定的历史内容。
- 会话持久化不等于允许业务模块将全部历史对话用于任意分析。

### 3.2 上下文边界

- 基座根据业务模块明确提供的材料组装模型调用上下文，并处理上下文长度与调用限制。
- 基座不自动扫描用户全部历史对话，也不自行决定某段历史内容是否适合业务分析。
- 用户在当前会话主动提供的文本或文件内容属于本次上下文；它不因进入上下文而自动成为长期记忆。

## 4. 模型调用与版本管理

### 4.1 调用能力

- 业务模块通过基座发起模型调用，不直接调用模型供应商。
- 基座负责模型路由、调用执行、失败处理和返回调用结果。
- 基座向业务模块返回模型结果及必要的调用元数据；业务模块决定结果是否可展示或继续使用。

### 4.2 版本与可追溯性

- 记录模型标识和版本。
- 支持业务模块指定或选择允许使用的模型策略。
- 调用记录可以关联会话、User 和业务模块，以支持问题排查与成本核对。

## 5. 通用记忆生命周期

### 5.1 基座职责

- 保存、查询、修改和删除长期记忆。
- 管理记忆候选的通用状态：待确认、已确认、已拒绝或已撤回。
- 记录记忆的 User 归属、来源引用、版本和确认状态。
- 执行用户对记忆的保存、修改、拒绝、撤回和删除操作。
- 保证未经确认或未经授权的候选内容不进入长期记忆。

### 5.2 与业务模块的边界

- 基座不判断候选内容的领域含义、证据是否充分或何时应当发起确认。
- 业务模块负责生成候选、决定候选分类和表达、说明依据与不确定性，并决定确认时机。
- 用户在业务模块中完成一次确认交互后，基座负责执行对应的通用记忆状态变更。

## 6. 成本审计

- 记录模型调用的成本相关信息，以支持成本核对和异常排查。
- 成本数据关联调用、User 和业务模块。
- 成本审计不负责定义业务价值、业务质量或用户体验指标。

## 7. 基座自身运行保障

- 监控模型调用、会话服务和记忆服务等基座能力自身的运行状态与异常。
- 记录必要的工程日志，支持故障定位和恢复。
- 不对外承担统一的业务指标上报、业务质量评估或领域风险审计能力。

## 8. MVP 非目标

- 租户、组织成员关系和 SSO。
- 跨 User 数据共享或自动关联。
- 统一业务监控平台。
- 领域规则插件机制。

未来演进事项见 [[future-evolution-todo]]。
