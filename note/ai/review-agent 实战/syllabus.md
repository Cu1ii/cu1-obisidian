# review-agent 实战 · 课程大纲

> 这份大纲定义了完成本课题后你将掌握的所有能力。
> 学习深度：标准
> 文档数量因人而异，但掌握内容不打折扣。

## 核心掌握项

完成本课题后，你将能够：

### 一、定义 review-agent 的边界与输入输出
- [x] 能够界定 Java review-agent 第一版的范围：只关注 correctness 与 security，不处理 style
- [x] 能够把一次代码评审任务抽象成输入、上下文、约束、输出 4 个部分
- [ ] 能够设计一份高 Precision 的 finding 输出格式，并定义“什么证据才够报出来”

### 二、沉淀可迁移的评审规则
- [ ] 能够为 Java 增量代码总结第一版 correctness 规则，并区分高价值规则与噪声规则
- [ ] 能够为 Java 增量代码总结第一版 security 规则，并给出触发条件与误报边界
- [ ] 能够把规则写成平台无关资产，使其可迁移到 Claude Code、Codex 等不同 Agent 环境

### 三、搭建最小可用工作流
- [ ] 能够设计一条最小可用的 review 工作流：读取 diff、补充上下文、生成 findings、人工复核
- [ ] 能够设计 prompts、schema、规则文件之间的职责分工，避免所有逻辑都塞进单个 Prompt
- [ ] 能够用真实 diff 构造第一版样本，并记录每条 finding 的真假与证据

### 四、评估、迭代与迁移
- [ ] 能够用 Precision、误报类型、漏报类型、耗时、成本评估第一版 review-agent
- [ ] 能够针对误报与漏报迭代规则、Prompt 与上下文策略，而不是凭感觉改动
- [ ] 能够比较 Claude Code 与其他 Agent 平台的差异，并识别哪些资产可以直接迁移

## 不在本课题范围内

- 不系统讲解通用静态分析理论，也不覆盖编译器级规则引擎实现。
- 不追求第一版就支持多语言；本课先聚焦 Java。
- 不处理代码风格、美化、命名偏好等 style 问题。
- 不覆盖完整 CI/CD 平台接入；先把单次 review 跑通并可评估。
