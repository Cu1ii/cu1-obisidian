## 一、知识图谱

这门课的主线，不是按工具名展开，而是按 AI 工程系统的真实结构展开。

### 1. 总体地图

AI 工程核心不是研究模型为什么聪明，而是：

> **把不稳定的模型能力，接进稳定的软件系统。**

围绕这个目标，可以把整套能力分成 5 段：

```text
输入 → 模型 → 工具 → 评估 → 交付
```

这 5 段是你之后理解任何 AI 应用、Agent、RAG、代码助手、知识库问答系统的总骨架。

### 2. 模型调用层

你已经建立了对一次模型调用的工程理解：

- 模型读的是 `messages`，不是“自己记得上下文”
- token 决定上下文长度、成本和延迟
- context window 决定一次调用最多能看多少内容
- 参数决定稳定性和发散程度
- 模型输出不是最终结果，必须经过解析和校验

一句话概括：

> **模型调用不是魔法，而是一次带上下文、参数和输出校验的远程函数调用。**

### 3. Prompt 层

Prompt 不是咒语，而是接口契约。

你已经掌握了稳定 Prompt 的 5 个基本模块：

- 角色
- 任务
- 输入材料
- 约束
- 输出格式

以及 Prompt 失效的常见原因：

- 任务边界模糊
- 输入材料不足
- 指令和数据混在一起
- 输出格式不固定
- 约束冲突
- 上下文噪声过多
- 缺边界样本
- 没有输出校验

### 4. AI 应用层

你已经能把一个 AI 应用拆成 5 个模块：

```text
上下文构造 → 模型调用 → 状态管理 → 工具执行 → 结果展示
```

这是从 Demo 走向工程的关键跃迁。

- 上下文构造：决定给模型看什么
- 模型调用：决定如何调用模型
- 状态管理：决定当前流程走到哪一步
- 工具执行：决定模型能查什么、做什么
- 结果展示：决定用户看到什么、如何信任结果

### 5. Agent 层

你已经建立了对 Agent 的工程理解：

> **Agent 不是更长的 Prompt，而是“模型决策 + 状态机 + 工具执行 + 安全边界 + 终止条件”组成的系统。**

核心循环：

```text
Observe → Decide → Act → Update → Stop
```

你也已经区分：

- 短期上下文
- 会话状态
- 长期记忆

并理解：封装型 Agent（Claude Code / Codex）把这些能力藏到了平台内部，而不是 Prompt 本身自动拥有。

### 6. 稳定性层

你已经掌握 AI 应用上线前必须处理的 5 个稳定性问题：

- 错误处理
- 重试
- 限流
- 缓存
- 成本控制

对代码 review Agent，这些能力尤其重要，因为它天然会面对：

- 大 diff
- 多文件上下文
- 只读与写操作边界
- 缓存命中与失效
- 成本失控
- 工具重复调用

### 7. 风险与安全层

你已经建立对 AI 系统 5 类核心风险的识别能力：

- 幻觉
- 越权工具调用
- 提示注入
- 数据泄露
- 不可复现输出

这 5 类风险对代码 review Agent 尤其关键，因为代码、注释、配置、日志、PR 内容本身就可能是不可信输入。

### 8. 评估与迭代层

你已经掌握评估不能靠感觉，而要靠样本与指标。

关键评估概念：

- Precision：报出来的问题有多少是真的
- Recall：真实问题里找到了多少
- False Positive Rate：误报率
- Time Cost：耗时
- Token / Money Cost：成本

并且你已经理解：

> **代码 review Agent 第一版应优先提高 Precision，而不是 Recall。**

因为误报会直接摧毁信任。
