## terms 查询与字段类型

原文：[[note/ES/ES 慢查询过多治理《最佳实践》#^terms-field-type|一、业务查询逻辑：terms 查询非 keyword 字段类型]]。

### 为什么 keyword 的精确查询可能更快

原文中的 `channels` 是 `integer` 字段。常规默认配置下，数值字段和 `keyword` 使用不同的检索结构：

- **数值字段使用 BKD 树**，擅长范围查询；按一组离散值做 `terms` 匹配时，需要通过树结构定位匹配数据。
- **`keyword` 使用倒排索引**，可以在词项词典中查找目标值，再读取对应的文档 ID 列表，更适合「值等于什么」「值在某个列表中」这类查询。

因此，用户 ID、渠道 ID 等只用于精确匹配的标识符，即使由数字组成，也可以用 `keyword`。**优势来自检索结构更适合查询方式，而不是把数字变成字符串本身。** 这不代表数值字段一定慢，实际收益仍需测试。

出处：[Elastic 官方文档：Mapping numeric identifiers](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/number#mapping-numeric-identifiers)。

## multi-fields 与 keyword 子字段

原文：[[note/ES/ES 慢查询过多治理《最佳实践》#^multi-fields-keyword|场景一：通过 multi-fields 增加 keyword 子字段]]。

**multi-fields 就是把同一个字段值，按不同类型分别建立索引表示。** 例如，保留 `long`，再增加一个 `keyword` 子字段：

```json
{
  "user_id": {
    "type": "long",
    "fields": {
      "keyword": {
        "type": "keyword"
      }
    }
  }
}
```

- `fields` 下第一层 `"keyword"` 是**自己指定的子字段名**，可以改成 `exact`；对应的查询路径就从 `user_id.keyword` 变为 `user_id.exact`。
- `"type": "keyword"` 中的 `"keyword"` 才是 **ES 规定的字段类型**。

写入 `"user_id": 1001` 时，ES 会同时为 `user_id` 建立数值索引表示，为 `user_id.keyword` 建立倒排索引表示。范围查询用前者，`terms` 精确匹配用后者。

**这是同一个 ES 索引、同一篇文档中的两种索引表示，不是新建另一个 ES 索引。** 原始 `_source` 不变，业务也不需要额外写入子字段，但会增加存储和写入开销。

出处：[Elastic 官方文档：Multi-fields](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/multi-fields)。

## terms size 过大为什么影响查询效率

原文：[[note/ES/ES 慢查询过多治理《最佳实践》#^terms-size|一、业务查询逻辑：terms size 过大]]。

这里的 **terms size 是 `terms` 数组中传入的值的数量，不是返回结果的 `size`**。精确匹配一个值很快，不代表同时匹配几千个值、合并结果也没有成本。

以 `keyword` 字段为例，主要有三部分开销：

1. **查找更多词项**：需要处理更多目标值，并在词项词典中定位匹配项；即使最终没有命中文档，也仍有查询准备和词典查找成本。
2. **读取并合并文档 ID**：每个值可能对应一份倒排列表，需要将匹配文档合并、去重。值越多、对应的文档越多，可能需要处理的数据就越多。Lucene 会使用位集合、迭代器等方式优化，并不是执行几千次独立查询，但查找与合并仍有成本。
3. **分片和并发放大开销**：涉及多个分片时，各分片都要在自己的数据上执行匹配，而不是把查询值平均分给各分片。大量此类请求并发执行，可能耗尽 CPU 和内存资源，导致搜索请求排队、延迟上升、超时或被拒绝。

**1,000 是原文给出的业务经验值，不是 ES 的通用性能阈值。** 实际成本还取决于字段类型、命中文档量、分片数、其他过滤条件和并发量，是否需要扩容应以压测为准。ES 默认允许一个 `terms` 查询最多包含 65,536 个值，由 `index.max_terms_count` 控制；这是数量上限，不是性能保证。返回结果设为 `size: 10`，也不代表只处理 10 个查询值。

出处：[Elastic：Terms query](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-terms-query)、[Lucene：TermInSetQuery 源码及说明](https://github.com/apache/lucene/blob/main/lucene/core/src/java/org/apache/lucene/search/TermInSetQuery.java)、[Elastic：Search concurrency and parallelism](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/search-shard-routing#search-concurrency-and-parallelism)。具体执行方式随字段类型及 Lucene 版本而异。
