## 正文内容

很多人听到 Agent，会想成「一个更聪明的聊天机器人」。这不准确。

更工程化的定义是：

> **AI Agent 是一个由模型驱动决策、能在循环中观察状态、选择动作、调用工具、更新上下文，并在满足条件时停止的系统。**

关键词有 5 个：

1. **循环**：不是一次模型调用结束，而是多步推进。
2. **观察**：读取用户输入、工具结果、当前状态。
3. **决策**：决定下一步回答、追问还是调用工具。
4. **工具**：通过外部系统查数据或执行动作。
5. **终止**：知道什么时候结束，避免无限循环或乱调用。

## 一、普通 AI 应用和 Agent 的区别

普通 AI 应用可能是一次调用：

```text
用户输入 → 构造 Prompt → 模型回答 → 展示结果
```

Agent 更像一个循环：

```text
观察当前状态
  ↓
模型决策下一步动作
  ↓
如果要调用工具：系统执行工具
  ↓
把工具结果写回上下文和状态
  ↓
再次观察
  ↓
继续，直到满足终止条件
```

### 例子：订单物流查询

普通应用：

```text
用户：我的订单 88321 到哪了？
模型：请自行打开订单页面查看。
```

Agent：

```text
用户：我的订单 88321 到哪了？
系统：构造上下文
模型：决定调用 getOrderStatus(88321)
系统：校验权限并调用工具
工具：返回物流状态
模型：基于工具结果生成回复
系统：展示结果
```

Agent 的价值不在于「更会聊天」，而在于**能把模型判断和外部动作串起来**。

## 二、Agent 最小循环：Observe → Decide → Act → Update

最小 Agent 可以用 4 步理解。

### 1. Observe：观察

观察不是让模型随便看所有东西，而是系统整理出当前必要信息：

- 用户最新输入
- 当前会话状态
- 已知槽位，如订单号
- 可用工具列表
- 上一步工具结果
- 系统规则和安全边界

### 2. Decide：决策

模型根据观察结果，输出下一步动作。

常见动作：

- `ANSWER`：直接回答用户。
- `ASK_USER`：向用户追问缺失信息。
- `CALL_TOOL`：调用某个工具。
- `FINISH`：任务完成。
- `FAIL`：无法完成，给出原因。

### 3. Act：行动

行动由工程系统执行，不是模型直接执行。

如果模型输出：

```json
{
  "action": "CALL_TOOL",
  "toolName": "getOrderStatus",
  "arguments": {
    "orderId": "88321"
  }
}
```

系统要做：

1. 校验 action 合法。
2. 校验工具存在。
3. 校验参数格式。
4. 校验用户权限。
5. 执行工具。
6. 记录日志。

### 4. Update：更新

工具结果回来后，系统更新状态：

- 已经查询过哪个订单
- 工具成功还是失败
- 是否需要用户补充信息
- 是否达到终止条件

然后进入下一轮。

## 三、用 Java 表达最小 Agent

先定义 Agent 动作。

```java
public enum AgentActionType {
    ANSWER,
    ASK_USER,
    CALL_TOOL,
    FINISH,
    FAIL
}

public record AgentDecision(
    AgentActionType actionType,
    String messageToUser,
    ToolCall toolCall,
    String reason
) {}

public record ToolCall(
    String toolName,
    Map<String, Object> arguments
) {}
```

再定义 Agent 运行上下文。

```java
public record AgentRunContext(
    String sessionId,
    UserContext userContext,
    ConversationState state,
    List<Message> messages,
    List<ToolSpec> availableTools
) {}
```

最小 Agent 接口：

```java
public interface AiAgent {
    AgentResult run(AgentRunContext context);
}

public record AgentResult(
    boolean finished,
    String responseToUser,
    ConversationState newState
) {}
```

一个简单执行器：

```java
public class AgentRunner {
    private final ModelClient modelClient;
    private final OutputParser<AgentDecision> decisionParser;
    private final OutputValidator<AgentDecision> decisionValidator;
    private final ToolExecutor toolExecutor;
    private final StateManager<ConversationState> stateManager;

    public AgentResult run(UserRequest request) {
        ConversationState state = stateManager.load(request.sessionId());

        for (int step = 0; step < 5; step++) {
            AgentRunContext context = buildContext(request, state);
            ModelResponse modelResponse = modelClient.call(context.messages(), ModelOptions.lowTemperature());
            AgentDecision decision = decisionParser.parse(modelResponse.rawText());

            ValidationResult validation = decisionValidator.validate(decision);
            if (!validation.valid()) {
                return AgentResult.failed("我暂时无法可靠处理这个请求，请补充信息或稍后重试。", state);
            }

            if (decision.actionType() == AgentActionType.ANSWER
                    || decision.actionType() == AgentActionType.FINISH) {
                stateManager.save(request.sessionId(), state);
                return new AgentResult(true, decision.messageToUser(), state);
            }

            if (decision.actionType() == AgentActionType.ASK_USER) {
                state.waitForUserInput(decision.reason());
                stateManager.save(request.sessionId(), state);
                return new AgentResult(true, decision.messageToUser(), state);
            }

            if (decision.actionType() == AgentActionType.CALL_TOOL) {
                ToolResult toolResult = toolExecutor.execute(decision.toolCall(), request.userContext());
                state.addToolResult(toolResult);
                continue;
            }
        }

        return AgentResult.failed("任务步骤过多，已停止自动处理。", state);
    }
}
```

这段代码不需要你现在完全实现。你要抓住结构：**Agent 不是一个 Prompt，而是一个循环控制器**。

## 四、Agent 的记忆：别和状态混淆

Agent 里常说 memory，但工程上至少分 3 类。

### 1. 短期上下文

当前对话里最近几轮消息。

用途：让模型知道刚才发生了什么。

风险：太长会稀释重点。

### 2. 会话状态

当前任务流程状态。

例如：

```java
public enum OrderQueryStep {
    WAITING_FOR_ORDER_ID,
    WAITING_FOR_PERMISSION_CHECK,
    WAITING_FOR_TOOL_RESULT,
    READY_TO_ANSWER,
    FINISHED
}
```

用途：让系统知道流程走到哪一步。

风险：状态机设计不清，会导致重复调用工具或跳步。

### 3. 长期记忆

跨会话保存的用户偏好、历史摘要、常用信息。

例如：

- 用户偏好 Java 示例。
- 用户常用项目类型。
- 用户经常查询的知识库范围。

用途：个性化和减少重复沟通。

风险：过期、错误、隐私、越权。

### 关键判断

> **短期上下文给模型看；会话状态给系统控流程；长期记忆给系统做个性化。三者不能混成一坨。**

## 五、Agent 的工具：不是越多越好

给 Agent 工具，等于给它行动能力。行动能力越大，风险越大。

工具设计要遵守 5 条规则。

### 1. 工具要小而明确

差：

```text
manageOrder
```

它能查、改、退、取消，边界太大。

好：

```text
getOrderStatus
requestRefund
cancelOrder
```

每个工具职责单一，权限好控。

### 2. 工具参数要强类型

Java 里不要用一坨 `Map<String, Object>` 到处传。

更好：

```java
public record GetOrderStatusInput(
    String orderId
) {}

public record RequestRefundInput(
    String orderId,
    String reason
) {}
```

强类型能减少参数错误。

### 3. 工具执行前必须校验权限

```java
if (!permissionChecker.canQueryOrder(userId, orderId)) {
    throw new PermissionDeniedException("用户无权查询该订单");
}
```

模型说能查，不代表真能查。

### 4. 敏感工具要确认

例如：

- 退款
- 删除数据
- 发邮件
- 提交审批
- 支付或转账

这些工具不应该由模型一次决策直接执行。应该先生成确认信息，让用户确认后再执行。

### 5. 工具结果要重新进入上下文

工具返回结果后，不能让模型凭记忆回答。系统要把工具结果作为新材料放回上下文。

## 六、Agent 的终止条件：防止无限循环

Agent 必须知道什么时候停。

常见终止条件：

1. 已经生成最终答案。
2. 需要用户补充信息。
3. 工具调用失败且无法恢复。
4. 达到最大步骤数。
5. 达到最大成本。
6. 触发权限或安全限制。
7. 检测到重复动作。

### 最大步骤数

最简单有效：

```java
for (int step = 0; step < maxSteps; step++) {
    // Agent loop
}
```

如果超过 `maxSteps`，停止并返回兜底信息。

### 重复动作检测

例如模型连续 3 次调用同一个工具、同一个参数：

```text
getOrderStatus(orderId=88321)
getOrderStatus(orderId=88321)
getOrderStatus(orderId=88321)
```

这通常表示循环卡住了。系统应该停止。

### 成本限制

Agent 多轮调用模型和工具，成本可能失控。要限制：

- 最大模型调用次数
- 最大输入 token
- 最大输出 token
- 最大工具调用次数
- 单次请求总超时

## 七、最小可用 Agent 设计清单

设计一个最小 Agent 前，先填这个清单。

### 1. 目标

这个 Agent 只做什么？明确一句话。

例：只帮助用户查询订单物流，不处理退款、不修改地址。

### 2. 输入

用户会给什么？系统能拿到什么？

例：用户文本、用户 ID、会话 ID。

### 3. 状态

任务有哪些步骤？缺什么信息时要追问？

例：等待订单号、校验权限、查询物流、生成回复。

### 4. 工具

需要哪些工具？哪些是只读？哪些是敏感操作？

例：`getOrderStatus` 是只读工具；`requestRefund` 是敏感工具。

### 5. 输出

最终给用户什么？是否需要依据、按钮、错误提示？

例：物流状态、更新时间、预计送达、无法查询原因。

### 6. 终止条件

什么情况下结束？什么情况下暂停等用户？什么情况下失败？

例：查到物流后结束；缺订单号时追问；无权限时失败。

## 八、Agent 新手最常见 5 个错误

### 1. 让 Agent 什么都做

「你是万能助手」通常不是好 Agent。范围越大，越难评估、越难控风险。

### 2. 没有状态机

只靠历史对话判断进度，容易重复问、重复查、跳步。

### 3. 工具权限太宽

模型能调用太多工具，风险扩大。先给少量只读工具，再逐步扩展。

### 4. 没有终止条件

Agent 循环必须有硬停止条件，否则会无限工具调用或无限追问。

### 5. 没有评估样本

Agent 看起来能跑，不代表稳定。需要用固定场景测试：缺订单号、无权限、工具失败、多个订单号、用户恶意输入。

## 九、你现在要掌握的一句话

> **Agent 不是「一个更长的 Prompt」，而是「模型决策 + 状态机 + 工具执行 + 安全边界 + 终止条件」组成的工程系统。**

如果只记一个框架，记这个：

```text
Observe → Decide → Act → Update → Stop
```

对应工程模块：

```text
上下文构造 → 模型决策 → 工具执行 → 状态更新 → 终止判断
```

你能把这条链路讲清楚，就已经超过很多只会堆 Agent 框架名的人。
